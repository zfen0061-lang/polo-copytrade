# CopyTrade Studio

简体中文 · [English](README.md)

一个在本机运行的前后端项目：管理多个币安带单交易员，配置独立的跟随规则，通过可追溯的**模拟交易**验证自动跟单思路。

**当前 v0.1 只执行模拟订单，不接收币安交易密钥，不发送实盘订单。**此前命令行实验中的实盘接口原型没有接到本 App 的 API 中。

## 项目用途

当官方跟单名额已满，仍可能有用户希望研究交易员公开的买卖操作，再评估自己的自动跟随规则。本项目提供数据观察、参数管理和模拟验证的工作台。它不突破官方跟单名额，不读取隐藏仓位，也不保证公开数据足够及时、能够替代币安内部跟单。

## 已实现

- 中英文界面：总览、交易员管理、信号与延迟、运行与接入。
- 添加不同交易员的带单主页链接，切换查看对象；每位交易员有独立的配置和模拟仓位。
- 设置模拟预算、每笔保证金、杠杆、允许合约、价格止损、亏损预算、信号有效期、手续费假设与固定减仓比例。
- **多空统一使用 3% 最大不利跟随价差作为初始设置。**他在100开多，我们最高接受103；他在100开空，我们最低接受97。这是开仓价差，不是3%止损。
- SQLite 持久化账本、重复信号去重、模拟手续费与已实现/未实现盈亏。
- 本地模拟止损和亏损预算退出；全局暂停新增仓位，不影响已持有模拟仓位的止损检查。
- 区分过期开仓和迟到的平仓信号：过期开仓跳过，迟到平仓仅减少已有对应模拟仓位，不反手开仓。
- 来源标注时间、首次发现时间、可观测时差、决策报价、价差和跳过原因，支持 CSV 与配置导出。
- 无网络也可运行的合成演示；可选币安公开页面采集器，需要先核实权限、时区和页面兼容性。
- 本机 HTTP 服务，带 Host 检查、同源限制、会话 CSRF 令牌、请求大小限制与前端文本转义。

## 如何启动

需要 Python **3.10 或以上**。演示界面、后端和模拟引擎只依赖 Python 标准库，**不需要先装 npm 或 pip 包**。

在项目文件夹终端执行：

```powershell
python -m backend.server
```

浏览器打开 **http://127.0.0.1:8765**。Windows 也可以双击 `start.cmd`。Ctrl+C 停止服务；端口占用时加 `--port 8766`。

1. 在总览选择交易员，点击“启动模拟跟随”。
2. 调度器会生成演示信号，也可以手动点击“生成一条演示信号”。
3. 点击“测试 3% 价差拦截”，生成一条偏离5%的演示开仓，查看跳过原因。
4. 查看模拟仓位、订单、信号和日志。
5. 修改参数前，先暂停该交易员并平掉其模拟仓位。

默认显示“熬鹰资本”作为参考对象，名称不是身份认证结论。**演示模式下的价格、操作和盈亏全部是合成数据，不代表该交易员的真实行为。**初始金额、杠杆等都是演示值，不是实盘建议。

## 在 VS Code 中开发

双击 `copytrade-studio.code-workspace`，或在 VS Code 选择“文件 → 打开文件夹”，选中项目文件夹。

“终端 → 运行任务 → Start CopyTrade Studio / 启动应用”可运行后端。已提供测试任务和 Python 调试配置；调试需要 VS Code 的 Python/debugger 扩展。

## 添加或切换其他交易员

点击“添加交易员”，填写名称和对应的币安带单主页链接，保存独立配置。在总览下拉框或交易员管理卡片中切换查看对象。

**切换查看不会转移资金、关闭旧仓位或暂停其他交易员。**要停止跟随某人，使用该交易员的暂停按钮；要退出其模拟仓位，使用平仓按钮。停止程序不会向币安发送平仓指令。

## 可选：采集公开操作

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-collector.txt
.venv\Scripts\python.exe -m playwright install chromium
.venv\Scripts\python.exe -m backend.server
```

在交易员配置中选“币安公开操作”前，需要核实该账号/用途是否获准自动读取该页面，并核实操作记录的时区。确认后再勾选访问确认框。程序不登录币安、不绕过验证码、不读取隐藏仓位，只读取中文公开操作列表。

第一次读取只建立历史基线，不补买旧交易。之后的新记录结合公开买卖一报价进入**模拟执行器**。历史无法衔接或采集出错时暂停并记录日志。该页面尚无已核实的固定延迟承诺，提高检查频率不能消除源头公开延迟。

## 技术结构

前端使用 HTML、CSS、JavaScript ES modules；后端使用 Python HTTP 服务；SQLite 保存配置、信号、模拟仓位、订单和日志。无需前端构建工具，适合在 VS Code 中直接阅读和运行。

| 目录 | 职责 |
|---|---|
| frontend | 中英文界面、交易员切换、参数编辑、表格与图表 |
| backend/server.py | HTTP API、静态文件、本机访问边界 |
| backend/core.py | 参数校验、模拟执行、数据库账本 |
| backend/feeds.py | 演示、可选公开采集、后台调度 |
| tests | 交易规则测试和内存 HTTP 请求测试 |
| docs | API 文档、验证结果及实盘接入待办 |

## 测试与验证限制

```powershell
python -m unittest discover -s tests -v
node --check frontend/app.js
```

第二条仅是可选 JavaScript 语法检查，需要 Node。HTTP 测试通过完整的内存字节流执行真实 HTTP 解析与响应，不依赖网络；不能代替真实端口、浏览器渲染或币安在线联调。详见 [验证记录](docs/VALIDATION.md)。

## 重要边界

- 模拟按买卖一价格假设足够流动性，尚未模拟盘口深度、资金费、强平、真实交易数量限制和全部执行失败情况，不能证明真实盈利。
- 止损填写的是价格变动百分比，不是保证金收益率。本地模拟止损只在程序运行并获得报价时生效，不是交易所止损，不能保护真实资金。
- 固定减仓比例是用户自己的规则，不是源交易员实际减仓百分比。隐藏总仓位时无法仅凭一次平仓数量确定该百分比。
- 页面缺少稳定成交ID时只能以字段指纹去重；公开记录可能聚合成交、延迟出现、漏读或改变格式。
- 当前没有连接交易账户；预算是本地模拟额度，不是真正隔离的交易所资金。
- 当前面向单机单用户，勿把本地服务直接暴露公网。GitHub 保存代码，GitHub Pages 不能运行此 Python 后端，Actions/Codespaces 也不是默认永久运行的交易服务器。
- 实盘执行器、交易所保护单与在线恢复验证需要单独实现，见 [实盘接入边界](docs/PRODUCTION.md)。
